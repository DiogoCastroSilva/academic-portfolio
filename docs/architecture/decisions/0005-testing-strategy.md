# ADR-0005: Testing strategy

- **Status:** Accepted
- **Context:** The project needs a unit-testing framework for content-processing logic (frontmatter parsing, image resolution, link rewriting, DEPLOYMENT_URL handling). An older version of the project used Jest alongside Vitest, creating redundancy.
- **Decision:** Use **Vitest 4.x** as the sole unit-test framework. Remove all Jest-related configuration and dependencies.
- **Alternatives considered:**
  - **Jest:** Already removed. Would add a separate test runner, additional configuration, and duplicate coverage tooling.
  - **React Testing Library + Vitest:** `@testing-library/react` was installed but never imported in any test. Removed. If component-level testing becomes necessary, it can be added as a targeted dev dependency.
- **Consequences and trade-offs:**
  - Vitest runs via `npx nx run-many --target=test` across all library projects that have a `vitest.config.*` file.
  - The `passWithNoTests` pattern is not used — projects without tests (e.g., `projects`, `publications` libraries) do not register a `test` target, so they are simply skipped by `run-many`. The `utils` library has its own `vitest.config.mts` and `test` target since it provides shared test helpers that are themselves unit-tested.
  - `@vitest/ui` was removed (not used in CI); coverage remains configured per-project via v8 provider.
- **Accessibility testing:** A shared `expectNoA11yViolations` helper is provided via `@academic-portfolio/utils/test-helpers/a11y` for `apps/main` test files and locally within `libs/navigation/src/lib/test-utils/` for navigation tests. This helper wraps `vitest-axe` and throws a descriptive error when accessibility violations are found. Common Next.js mocks (`next/navigation`, `next/link`) are centralized in global setup files (`test-setup.ts`) to reduce boilerplate. The `next/link` mock itself is shared from `@academic-portfolio/utils/test-helpers/next-mocks`.
- **Evidence or validation:**
  - `libs/content` has 236 tests (87 create-content-library + 47 profile + 48 marked-extensions + 39 sanitize-html + 15 constants) covering all content-processing scenarios including publication-specific field parsing and validation, URL resolution, semantic figure rendering, gallery detection, raw HTML postprocess, and XSS sanitization.
  - `libs/navigation` has 104 tests validating the navigation configuration and component a11y.
  - `libs/design-system` has 50 tests covering ContentImage, Pagination, Breadcrumb, ChevronIcon, and Tag components with a11y, reduced-motion, and rendering assertions.
  - `apps/main` has 425 component tests — including About-page feature tests (AboutHero, EducationTimeline, ResearchInterests, SkillsGrid), content feature tests (AboutSection, ContentCardSection, ContentDetail, Footer), collection/page tests, structured-data, SEO, pagination, sitemap, reduced-motion coverage, and no-JS integration tests.
  - `libs/utils` has 8 tests validating the shared `expectNoA11yViolations` helper and utility functions.
  - Total: 823 tests across 54 test files. All pass: `npx nx run-many --target=test --all`.
- **Conditions for revisiting:** If browser-level integration testing is needed (e.g., for the mobile navigation toggle or ContentDetail rendering), a Playwright or Vitest Browser mode setup can be added.
